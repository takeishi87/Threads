## ─── 第1章：そもそも「Claude Code」って何？（完全初心者向け） ───

### 一言で言うと「AIプログラミングアシスタント」

Claude CodeはAnthropicが開発したAIツールで、主にプログラマー（コードを書く人）が使うことを想定した専用ツールだ。ChatGPTやClaude.aiのようなチャット型のAIとは少し違う。

「コードを書く」というのは、アプリやウェブサイトを作る命令文を書くこと。これが非常に複雑で時間がかかる作業なのだが、Claude Codeがあれば「こういう機能を作って」と日本語で話しかけるだけで、AIがコードを書いてくれる。

### ChatGPTやClaude.aiとどう違うの？

| 比べるポイント | ChatGPT・Claude.ai（チャット版） | Claude Code（専用ツール） |
|--------------|-------------------------------|------------------------|
| 使い方 | ブラウザでチャット | ターミナル（黒い画面）で操作 |
| 得意なこと | 文章を書く・質問に答える | コードを書く・ファイルを操作する |
| ファイル操作 | できない | パソコン内のファイルを直接読み書きできる |
| 連続作業 | 毎回頼む必要がある | 複数の作業を自動で続けてくれる |
| 対象ユーザー | 誰でも | 主にプログラマー・エンジニア |

### 使うと何が変わるか（before / after）

**Before（Claude Codeなし）：**
- コードのミスを探すのに1時間かかる
- 新しい機能を追加するたびに全部手作業
- 「このコードなんでエラーが出るの？」と悩み続ける

**After（Claude Codeあり）：**
- 「このコードのミスを探して」と頼めば数分で完了
- 「〇〇機能を追加して」と言えばAIが自動でコードを書いてくれる
- エラーの原因を即座に教えてくれる

## ─── 第3章：「Agent view」— 複数のAI作業を同時に管理する ───

### これは何？

2026年5月のWeek 20（v2.1.139〜）で追加された「Agent view（エージェントビュー）」は、複数のClaude Code作業を一画面でまとめて管理できる機能だ。

今まではClaude Codeに1つの仕事を頼んだら、それが終わるまで待つか、別のウィンドウを開いて別の作業を頼むしかなかった。それが、Agent viewを使えば「バグの修正」「プルリクエストのレビュー」「テストの調査」を同時に動かして、一覧で進捗を確認できるようになった。

### どう使うの？

ターミナル（黒い画面）で以下を入力するだけ。

```bash
claude agents
```

すると一画面に、進行中・入力待ち・完了済みのタスクが一覧で表示される。任意の行を選んで「アタッチ（接続）」すれば、その会話の詳細を見られる。`←`キーを押せばまた一覧に戻れる。

### 仕事でこう使える

たとえば、プログラマーなら朝出社してこんな使い方ができる。

1. 「今日のバグレポートを全部調べて修正案を出して」
2. 「昨日のプルリクエスト3件をレビューして」
3. 「本番環境のテストが落ちている原因を調べて」

この3つを同時にClaude Codeに依頼して、自分はコーヒーを飲みながら別の作業。Agent viewの画面でどれが完了したか確認して、必要なときだけ介入すればいい。

複数の作業を同時に任せて、人間は「確認・判断」だけに集中できる。これが実現すると、一人でこなせる仕事量が劇的に増える。

## ─── 第4章：「/goal」— 目標を言えばAIが自動でやり切る ───

### これは何？

`/goal`（ゴール）は、**完了条件を設定すれば、その条件が満たされるまでClaude Codeが自動で作業を続ける**機能だ（v2.1.139〜）。

今まではClaude Codeに作業を頼んでも、1回ごとに「次はこれをして」と指示する必要があった。それが`/goal`を使えば、「全テストが通って、コードチェックもクリアになるまで作業して」と一度言えば、あとは自動で試行錯誤しながら目標を達成してくれる。

### どう使うの？

```
> /goal all tests in test/auth pass and the lint step is clean
（日本語で説明：test/authのテストを全部通して、コードチェックもクリアにして）
```

この一言でClaude Codeが起動し、テストが失敗するたびに原因を調べて修正して、再テストして…という作業を自動で繰り返す。目標が達成されたら止まる。

### 仕事でこう使える

「新しい機能を追加したら全テストを通すまで修正してほしい」——これはプログラマーが日常的に行う作業だ。

今まで：
- コードを書く → テスト実行 → 失敗を確認 → 修正 → 再テスト → …を何十回も繰り返す（数時間かかることも）

/goalを使うと：
- 「全テストを通して」と一言言って離席 → 戻ってきたら完了している

特に「夜中に長時間かかる修正作業を走らせておきたい」というときに最高の機能だ。

## ─── 第5章：「/ultrareview」— クラウドで大規模コードレビュー ───

### これは何？

`/ultrareview`（ウルトラレビュー）は、**複数のAIエージェント（自律的に動くAI）がクラウド上で並列でコードを調べて、バグや問題点を洗い出してくれる**機能だ（v2.1.114〜、2026年4月のWeek 17から公開プレビュー）。

「コードレビュー」というのは、プログラマーがお互いのコードをチェックして問題を指摘し合う作業のこと。これが時間もかかるし、見落としも多い。`/ultrareview`はこの作業をAIが代わりにやってくれる。

### どう使うの？

今作業中のコードをレビューしたいとき：

```
> /ultrareview
```

特定のプルリクエスト（変更のまとまり）をレビューしたいとき：

```
> /ultrareview 1234
```

また、v2.1.120からはCIやスクリプトでも使えるコマンドラインツールが追加された：

```bash
claude ultrareview
```

### 仕事でこう使える

大事なコードの変更（認証機能・データベース操作など）をリリース前にチェックするとき、`/ultrareview`に丸投げするのがベストだ。

例えば、本番環境（実際のユーザーが使う環境）に公開する前に：

1. `> /ultrareview` で全体チェック
2. AIが「ここにセキュリティリスクがある」「このロジックは想定外の動作をする可能性がある」などを指摘
3. 指摘された箇所を修正してから公開

人間のレビュアーが1日かけてチェックするような作業を、数分でやってくれる。

## ─── 第6章：「Claude Opus 4.7」— より賢く・より速いAIモデル ───

### これは何？

2026年4月のWeek 16で登場した「Claude Opus 4.7」は、Anthropicが提供する最新・最高性能のAIモデルだ（v2.1.105〜）。

「モデル」とは、AIの頭脳部分のこと。Opus 4.7は「コーディング（プログラミング）」と「エージェント的タスク（自律的な作業）」に特化して改良されており、現在MaxプランとTeam Premiumプランのデフォルトモデルになっている。

### 新しい「effortレベル（effort level）」

Opus 4.7では「xhigh（エクストラハイ）」という新しい力の入れ加減レベルが追加された。

| レベル名 | 特徴 | 向いている作業 |
|---------|------|--------------|
| low | 速いが雑 | 簡単な質問 |
| medium | バランス型 | 日常的なコーディング |
| high | 精度重視 | 複雑なコード |
| xhigh（新） | 最高精度 | 重要なコーディング・エージェント作業 |
| max | 最大出力（時間かかる） | 超複雑な問題 |

「xhigh」はOpus 4.7のデフォルト設定になっており、ほとんどのコーディング作業で最良の結果を出せる設定だという。

```
> /model opus
> /effort xhigh
```

この2行で最高性能モードに切り替えられる。

### Fast mode（ファストモード）がOpus 4.7に対応

「Fast mode（ファストモード）」という機能は、通常の2.5倍の速さでAIが動く特別な設定だ。

Week 20（v2.1.139〜）から、このFast modeがOpus 4.7をデフォルトで使うようになった。速さと精度のどちらも欲しい人には最高の選択肢になる。

料金は1MTok（100万トークン）あたり$30/$150で、Opus 4.6のFast modeと同じ料金設定だ（※これは概算表示例です。実際の料金はプランや使用量により変動します）。

### 仕事でこう使える

日常的なコーディング作業は「high」レベルで十分だが、本番リリース前の重要な作業や、バグが混入しやすい複雑なロジックを書くときは「xhigh」に切り替えると、AIがより慎重かつ精度高く作業してくれる。

## ─── 第7章：「Routines」— 自動化をスケジュールで動かす ───

### これは何？

「Routines（ルーティン）」は、Claude Code on the Web（ウェブブラウザ版）で使える機能で、**スケジュールやGitHubのイベントをトリガーにして、自動でAIエージェントを動かせる**機能だ（Week 16〜）。

「GitHubのイベント」とは、例えば「プルリクエストが作られたとき」「リリースが公開されたとき」などのこと。

### どう使うの？

Claude Code on the Web（`claude.ai/code`）でルーティンを設定する。以下のトリガー（きっかけ）が使える：

| トリガー種類 | 説明 | 例 |
|------------|------|---|
| スケジュール | 決まった時間に実行 | 毎朝9時にPRレビュー |
| GitHubイベント | GitHubの操作で実行 | PRが作られたら自動レビュー |
| API呼び出し | 外部システムから実行 | 別のシステムがトリガーを送る |

CLIからも設定できる：

```
> /schedule daily PR review at 9am
```

### 仕事でこう使える

例えばこんな自動化が設定できる：

- **毎朝9時に前日のプルリクエストを自動レビュー**して結果をSlackに通知
- **新しいプルリクエストが作られたら自動でコードレビュー**を実行
- **週次のコード品質チェック**を月曜朝に自動実行

「いつか自動化したい」と思っていた繰り返し作業を、一度設定すれば勝手に動き続けてくれる。

## ─── 第8章：「モバイルプッシュ通知」— スマホで作業完了を受け取る ───

### これは何？

長時間かかるAI作業を走らせているときに、**スマートフォンにプッシュ通知が届く**機能だ（Week 16〜）。

「Remote Control（リモートコントロール）」機能と連携して動く。Remote Controlは、Claude Codeが動いているパソコンをスマホから操作できる機能で、モバイルプッシュ通知もその一部だ。

### どう使うの？

`/config`（設定メニュー）で「Push when Claude decides」をオンにする。あとは普通にClaude Codeに作業を頼むだけ。

特定の通知タイミングを指定することも可能：

```
> notify me when the tests pass
（テストが通ったら通知して）
```

### 仕事でこう使える

「大規模なリファクタリング（コードの整理・書き直し）を頼んで、終わったら知らせて」という使い方が典型的だ。

1. 退社前にClaude Codeに大きな作業を頼む
2. 電車で帰宅しながらスマホで通知を待つ
3. 「完了しました」または「判断が必要です」の通知を受け取る
4. 必要であればスマホのRemote Controlから指示を追加する

「作業が終わるまでパソコンの前で待ち続ける」必要がなくなる。

## ─── 第9章：「Auto mode」— 安全な操作を自動承認する ───

### これは何？

「Auto mode（オートモード）」は、2026年3月のWeek 13（v2.1.83〜）から登場した機能で、**安全な操作を自動的に承認して、リスクのある操作だけ確認を求める**モードだ。

今まではClaude Codeがファイルを変更するたびに「本当に実行していいですか？」と聞いてきた。Auto modeをオンにすると、「明らかに安全な操作」は自動でOKになり、「危険かもしれない操作」だけ確認が来るようになる。

### 「hard deny rules（ハードデナイルール）」も追加

Week 19（v2.1.128〜）では、「何があっても絶対に自動実行しない操作」を設定できる「hard deny rules」が追加された。

例えば「データベースの削除操作は絶対に自動実行しない」というルールを設定しておけば、Auto modeがオンでもその操作だけは必ず確認が入る。

### 仕事でこう使える

設定ファイルの場所（`.claude/settings.json`）に以下のような設定を追加する：

```json
{
  "autoMode": {
    "hard_deny": [
      { "command": "rm -rf" },
      { "command": "DROP TABLE" }
    ]
  }
}
```

「ファイルを大量に読む・書く作業はどんどん自動実行してほしいが、削除だけは必ず確認したい」という要望に完璧に応えてくれる。

## ─── 第10章：「Computer use」— マウス・キーボード操作も自動化 ───

### これは何？

「Computer use（コンピュータユーズ）」は、2026年3月のWeek 14（v2.1.86〜）で追加された機能で、**Claude CodeがパソコンのGUI（グラフィカルな画面）を操作できる**ようになった。

今まではコードの読み書きがメインだったClaude Codeが、実際に画面上でマウスをクリックしたり、アプリを起動したりできるようになった。

### どう使うの？

現在は「research preview（研究段階のプレビュー）」なので、まだ完全には安定していない段階だ。日常業務への本格導入は、もう少し安定してからがおすすめ。まずは「こんなこともできるんだ」と体験してみる程度で試すのがいい。

使い方の例：

```
> ブラウザでこのサイトを開いて、フォームを入力して送信して
```

```
> このアプリの設定画面を開いて、この項目を変更して
```

### 仕事でこう使える

「コードを書いた後に、実際にブラウザで動作確認して、問題があったら修正して」という一連の作業を全部自動化できる。

今まで：
1. コードを書く（Claude Codeに任せる）
2. ブラウザで動作確認する（人間がやる）
3. 問題があれば修正する（Claude Codeに任せる）
4. 再度確認する（人間がやる）…

Computer useがあれば：
1. 「コードを書いて、ブラウザで確認して、問題があれば修正して」と一言言うだけで全部自動

## ─── 第11章：地味だけど助かる細かい改善 ───

大きな機能ほど注目されないが、日常の使い勝手を大きく変える細かい改善も多い。

### PR URLで前の作業を再開できるようになった

Week 18（v2.1.122〜）から、「前にClaude Codeでやった作業に戻りたい」というとき、**そのときに作ったGitHubのPR（プルリクエスト）のURLを貼るだけで、作業を再開できる**ようになった。

```
> /resume
（PRのURLを貼り付ける）
https://github.com/your-org/your-repo/pull/1234
```

今までは「あの作業はいつのセッションだっけ…」と探す必要があったが、PRのURLを控えておけばすぐに再開できる。

### Windowsで使いやすくなった

Week 18で、**Windowsパソコンでも「Git Bash（ギットバッシュ）」をインストールしなくてもClaude Codeが動く**ようになった。

「Git Bash」はWindowsで必要だったソフトウェアで、インストールが少し面倒だった。これが不要になり、PowerShell（ウィンドウズ標準のツール）で動くようになった。Windowsユーザーにとってはかなり嬉しい改善だ。

### コマンド履歴を全プロジェクトから検索できるようになった

Week 19（v2.1.129〜）から、`Ctrl+R`キーで過去のコマンドを検索するとき、**全プロジェクトの履歴から検索できる**ようになった。

「先週別のプロジェクトで使ったあのコマンドどんなだっけ？」という状況で、以前なら探し回る必要があったが、`Ctrl+R`で一発で出てくるようになった。

### セッションの要約（Rewindメニュー）

Week 20で、「Rewindメニュー（会話を巻き戻す機能）」に**「Summarize up to here（ここまでを要約する）」**オプションが追加された。

長い会話が続いてAIの記憶容量（コンテキスト）が圧迫されてきたとき、古い部分だけをギュッと要約して空き容量を作れる。最近の会話はそのまま残るので、自然に会話を続けられる。

### サインインがしやすくなった

Week 18（v2.1.126〜）から、**ブラウザのコールバック（自動返送の仕組み）が動かない環境でも、コードを貼り付けてサインインできる**ようになった。

WSL2（ウィンドウズ上のLinux環境）やSSH（リモートサーバーへの接続）、コンテナ（隔離された実行環境）など、特殊な環境でも使いやすくなった。

### プロジェクトのデータを一括削除できるようになった

Week 18（v2.1.126〜）で`claude project purge`コマンドが追加された。特定のプロジェクトの会話履歴やファイル履歴を全部きれいに削除できる。

```bash
# 削除前に何が消えるか確認
claude project purge --dry-run

# 実際に削除
claude project purge
```

容量を整理したいときや、機密情報が入ったプロジェクトの履歴を消したいときに使える。

## ─── 第12章：今日から始める方法 ───

### Claude Codeのインストール

Claude Codeは`npm`（JavaScriptのパッケージ管理ツール）でインストールする。

```bash
npm install -g @anthropic-ai/claude-code
```

Week 16（v2.1.113〜）から、Windowsはネイティブバイナリ、MacはHomebrew、LinuxはAPT/RPMなど、各OSの標準的な方法でもインストールできるようになった。

**サインインは：**

```bash
claude auth login
```

これでブラウザが開くのでAnthropicのアカウントでログインする（Week 18からターミナルにコードを貼り付けてのログインも可能）。

### プランと料金

## ─── 第13章：初心者向け実践ガイド ───

### よくある不安への回答

**「プログラミングを知らなくても使えますか？」**

基本的な使い方はできるが、Claude Codeは主にプログラマー向けのツールだ。「コードを書いてもらう」だけなら使えるが、書いてもらったコードを理解したり、問題が起きたときに対処したりするにはプログラミングの知識があったほうがいい。

**「英語ができないとダメですか？」**

日本語で指示しても動く。コマンド（`claude agents`など）は英語だが、Claude Codeへの指示は日本語でOKだ。

**「高いパソコンが必要ですか？」**

Claude Code自体は軽いツールなので、普通のパソコンで動く。ただし、作業内容によってはパソコンの性能が影響することもある。

**「うっかり大事なファイルを消したりしませんか？」**

Auto modeでは「危険な操作」には確認が入る。また、Claude Codeはデフォルトで操作前に「これをしていいですか？」と聞いてくる設定になっている。

## ─── まとめ ───

2026年3月〜5月のClaude Codeアップデートは、「一人で複数の作業を並行して動かす」「目標を設定して自動でやり切る」「大規模なコードレビューをクラウドで行う」という3つの方向性が大きく進化した。

### 設定なしで今すぐ試せるもの

- **Agent view**：`claude agents`と打つだけで使える
- **/goal**：`/goal 条件`と書けばすぐ動く
- **セッション履歴検索（Ctrl+R）**：今すぐ使える
- **PR URLで再開**：`/resume`後にPR URLを貼るだけ

### 明日試してほしいもの

1. **`/ultrareview`でコードレビュー**：自分のコードに対して試すだけでいい
2. **`claude agents`でAgent viewを体験**：複数作業を並行して動かしてみる
3. **/goalで長い作業を自動化**：「全テストを通して」と言って離席してみる

Claude Codeのアップデートペースはとにかく速い。今後も毎週新しい機能が届くはずなので、公式の「What's New」ページ（`code.claude.com/docs/en/whats-new`）を定期的にチェックするのがおすすめだ。

一緒にこの進化についていきながら、日々の作業を少しずつ楽にしていこう。
